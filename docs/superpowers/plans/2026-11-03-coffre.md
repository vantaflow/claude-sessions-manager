# Coffre des PAT et secrets — plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal :** un menu « Coffre » qui garde les PAT Azure DevOps et autres secrets, partagés chiffrés entre machines, et donne à chaque session le PAT qui marche pour l'organisation de son dossier.

**Architecture :** `lib/vault/` (valeurs protégées par le système, métadonnées, choix du PAT, routes) ; synchro par le canal des conversations (R2, préfixe `sec-`), que les anciennes versions ignorent (une ligne de session inconnue deviendrait une session fantôme chez elles) ; injection dans l'environnement de `spawnSession`.

**Spec :** `docs/superpowers/specs/2026-11-03-memoire-ia-design.md`, § 6 et « Secrets — import / conflits / validation ».

## Global Constraints

- Jamais une valeur renvoyée à l'interface, sauf « Copier » (route dédiée, jeton complet, confirmation dans l'interface) ; jamais écrite en clair dans les données de l'app, sauf en mode test (`CSM_SECRETS_FILE_ONLY`) et sous Linux (fichier 0600, comme `lib/secrets.js`).
- Valeurs locales : macOS trousseau (service `csm-coffre`, compte = id) ; Windows DPAPI de l'utilisateur (`ConvertTo-SecureString`/`ConvertFrom-SecureString` par PowerShell, valeur par l'entrée standard) dans `DATA/vault-values.json` ; sinon fichier 0600.
- Cibles d'un secret (là où les outils le lisent hors session) : service du trousseau macOS (`/^[\w.@-]{1,100}$/`) et/ou variable d'environnement de l'utilisateur Windows (`safeEnvName`). Rien de propre à B3G codé en dur.
- PAT d'une session : organisation tirée du remote git (`dev.azure.com/<org>/…`, `<org>@vs-ssh.visualstudio.com`, `<org>.visualstudio.com`) en lisant `.git/config` (pas de processus : le lancement n'attend jamais) ; association organisation → PAT en cache, sinon PAT du dossier choisi à la main, sinon PAT par défaut ; vérification en arrière-plan (`GET https://dev.azure.com/<org>/_apis/connectionData`, 8 s) qui garde le premier PAT qui marche. Variables données : `AZURE_DEVOPS_PAT`, `AZURE_DEVOPS_EXT_PAT`.
- Conflits : empreinte (SHA-256) de la dernière valeur synchronisée (`base`) ; deux valeurs différentes changées des deux côtés → rien n'écrasé, conflit montré, choix de l'utilisateur. Valeur changée hors de l'app (cible relue à chaque synchro) → nouvelle valeur à diffuser.
- Réglage `syncSecrets` (vrai par défaut). Import des PAT déjà présents proposé une fois, avec confirmation.
- Livraison 3.63.0 (avec l'exclusion des sessions verrouillées de la mémoire IA), CHANGELOG, README, site, guide, `npm test`.

## Review Focus

- Valeur jamais dans une réponse d'API autre que `reveal`, ni dans les journaux → test `coffre : aucune valeur dans les réponses`.
- Remote git en SSH, en worktree (`.git` fichier), sans remote → `orgOf` testé sur ces cas.
- PAT refusé (401 ou 203 vers la page de connexion) → marqué refusé, le suivant essayé, avertissement si aucun → test `coffre : PAT par organisation`.
- Conflit à la première synchro et après modification des deux côtés → rien écrasé → test `synchro : coffre`.
- Suppression propagée, y compris d'une valeur jamais modifiée ici ; une valeur modifiée ici depuis n'est pas supprimée.

### Task 1 : valeurs protégées et cibles — `lib/vault/backend.js`
`open(DATA, { fileOnly, isMac, isWin }) -> { load(): Promise<Map<id,value>>, put(id, value), drop(id), writeTarget(t, value), readTarget(t) -> string|null, removeTarget(t) }`. Tests unitaires en mode fichier.

### Task 2 : organisation du dossier et vérification — `lib/vault/azure.js`
`orgOf(cwd) -> string|''` (lit `.git/config`, suit `gitdir:` et `commondir`) ; `verify(org, pat, { fetch, timeout }) -> 'ok'|'refused'|'error'`. Tests unitaires (dépôt https, ssh, visualstudio.com, worktree, sans remote ; réponses 200, 401, 203, réseau coupé).

### Task 3 : coffre, choix du PAT, routes — `lib/vault/index.js`, `server.js`
Métadonnées `DATA/vault.json` `{ items: [{ id, name, kind: 'azure-pat'|'secret', targets: { keychain?, env? }, hash, base, updated, origin, orgs: { org: { ok, at } } }], map: { orgs: { org: id }, folders: { portable: id }, def: id, updated }, conflicts: { id: { from, at } }, importOffered }`.
Routes : `GET /api/vault` (sans valeurs, avec avertissements et conflits), `POST /api/vault` (ajout), `PATCH /api/vault/<id>` (nom, valeur, cibles, défaut), `DELETE /api/vault/<id>`, `POST /api/vault/<id>/reveal`, `POST /api/vault/<id>/check`, `PUT /api/vault/folder` ({ cwd, id }), `POST /api/vault/conflict/<id>` ({ keep: 'local'|'remote' }), `GET|POST /api/vault/import`.
`ctx.vaultEnv(s) -> {}` dans `spawnSession` (après le nettoyage des variables). `ctx.vault` pour la synchro.
Tests serveur : ajout, aucune valeur dans les réponses, `reveal`, PAT par organisation avec un faux Azure DevOps (`CSM_AZDO_BASE`), PAT injecté dans la session (le faux claude écrit ses variables), import proposé une fois.

### Task 4 : synchro chiffrée — `lib/sync.js`, `sync-worker/src/index.js`
`syncVault()` sur le modèle de `syncAiMemory` : `sec-<id>` (secret + métadonnées), `sec-map` (associations) ; tombstone `{ deleted: true }` ; règles de conflit ci-dessus. Worker : `sec-%` gardé par le ménage. Tests : envoi chiffré, réception, conflit, suppression.

### Task 5 : menu Coffre et livraison
`public/vault.js`, `public/vault.css`, dialogue `#dlgVault` dans `index.html`, bouton de la barre latérale et commande de la palette, `i18n.js`. Version 3.63.0, docs, guide, captures, `npm test`.
